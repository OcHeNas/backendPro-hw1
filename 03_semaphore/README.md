# Счётный семафор

Мьютекс пускает внутрь одного. Семафор пускает N — он хранит число свободных
разрешений. `Acquire` забирает одно и блокирует, когда их не осталось,
`Release` возвращает и будит ждущего.

Придумал его Дейкстра, поэтому в старых текстах операции называются P и V
(от голландских *proberen* и *verhogen*).

Тонкость в `Acquire`: между «увидели, что разрешений ноль» и «уснули» кто-то
может успеть сделать `Release`. Поэтому засыпать нужно операцией, которая
проверяет значение и засыпает атомарно, а после пробуждения — перепроверять
всё заново в цикле: разрешение могли перехватить.

Мьютекс — это семафор на одно разрешение, но с важным отличием: у мьютекса
есть владелец, отпускать его должен тот же, кто захватил. Семафор ничей —
`Release` может позвать любой, и это нормально.

## Что реализовать

`New(n)`, `Acquire`, `TryAcquire`, `Release`, `Available`.

## Зачем нужно

Ограничить число одновременных запросов к базе, число параллельных загрузок,
размер пула соединений. В Go ту же роль часто играет буферизованный канал:
`make(chan struct{}, n)`.

## Реализация Python

Python: `semaphore.py`, класс `Semaphore(n)` и `New(n)`. CAS уменьшает положительный счётчик; Wait ожидает ноль. Каждый release вызывает Wake, даже если старый счётчик положителен: ранее разбуженный поток мог ещё не забрать разрешение. Нельзя будить только при переходе 0→1. Начальное значение может быть нулём, отрицательное запрещено; верхняя граница 2**32−1, переполнение вызывает OverflowError. Семафор не ограничен начальной ёмкостью. Владение потоками не отслеживается ни здесь, ни в учебном Mutex.
